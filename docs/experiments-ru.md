# Как запускать свои эксперименты

## Установка и первый запуск

Рекомендуется Python 3.12. Из каталога репозитория:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python -m unittest discover -s tests -v
python -m adaptive_grover_qaoa.runner configs/quick.json
```

В Windows активация: `.venv\Scripts\activate`.
Для использованных здесь версий NumPy/SciPy/Matplotlib дополнительно выполните
`python -m pip install -r requirements-repro.txt` (Python 3.12).
В облачной среде окружение уже установлено: можно сразу использовать `.venv/bin/python`.
После установки доступна и короткая команда `grover-experiment` вместо
`python -m adaptive_grover_qaoa.runner`.

## Своя конфигурация

Скопируйте `configs/quick.json`, например в `configs/my-experiment.json`.
JSON не поддерживает комментарии. Все поля обязательны; опечатки в названиях
параметров и методов приводят к ошибке до начала вычислений.

```json
{
  "qubits": [10, 12],
  "clause_sizes": [3, 4],
  "densities": {"3": 4.25, "4": 9.75},
  "depths": [5, 10, 20],
  "instance_seeds": [0, 1, 2],
  "methods": ["adaptive", "fixed_evt", "exact_greedy", "uniform"],
  "repeats": 100,
  "shots": 100,
  "warmup": 10,
  "optimizer_maxiter": 100,
  "sampling_seed": 2026,
  "save_histories": false
}
```

| Поле | Значение |
|---|---|
| `qubits` | Числа переменных/кубитов; без вспомогательных кубитов |
| `clause_sizes` | Размеры дизъюнктов; 3 для Max-3-SAT, 4 для Max-4-SAT |
| `densities` | Отношение условий к переменным, отдельно для каждого размера |
| `depths` | Фиксированные глубины схемы, в том числе адаптивной |
| `instance_seeds` | Seeds генератора **разных задач** |
| `methods` | Любое непустое подмножество четырёх методов |
| `repeats` | Число независимых повторений сэмплирования на каждой задаче |
| `shots` | Полный бюджет одного повторения каждого метода |
| `warmup` | Начальные шоты адаптивного алгоритма, уже входят в `shots` |
| `optimizer_maxiter` | Максимум поколений differential evolution на слой |
| `sampling_seed` | Seed независимого от генератора задач потока измерений |
| `save_histories` | Сохранять ли каждый измеренный битстринг; при `false` остаются итоги и события обновления |

Перебираются **все сочетания** qubits × clause_sizes × depths × instance_seeds.
Например, конфигурация выше задаёт 36 сочетаний и 14 400 повторений суммарно
по четырём методам. При 100 шотах — 1 440 000 измерений.
Число условий равно `round(n * density)` с округлением Python к ближайшему
чётному при точном попадании на половину. Например, 10 × 4.25 даёт 42 условия.
Фактическое число `m` всегда записывается в отчёты.

Одинаковые n, k, плотность и instance_seed задают одну и ту же формулу для
всех глубин и методов. Новая глубина не означает новую задачу. Значение
sampling_seed меняет измерения, но не формулы и не поиск углов. Поиск углов
детерминирован при фиксированных версии SciPy, instance_seed и бюджете.
Для независимой проверки качества оптимизатора нужен отдельный эксперимент
с его настройками; увеличение repeats не создаёт новые задачи или углы.

## Сравниваемые методы

- `adaptive`: исходная **необрезанная** EVT-оценка статьи, затем минимум первых
  warmup сэмплов, затем обновления при строгом улучшении. При каждом обновлении
  все слои подбираются заново с начала. Глубина остаётся фиксированной.
- `fixed_evt`: один подбор углов под исходную EVT-оценку; распределение
  остаётся неизменным на протяжении всего бюджета.
- `exact_greedy`: GM-QAOA с последовательной послойной оптимизацией истинной
  вероятности основного состояния. Предыдущие слои фиксируются. Это **oracle-
  ориентир**: он знает точный минимум и точно вычисляет целевую функцию.
  Его оптимизация не ограничена указанным бюджетом шотов; в практическом
  варианте пришлось бы отдельно учитывать измерения для обучения углов.
- `uniform`: независимые равномерные случайные битстринги, выбирается лучший.

У всех квантовых вариантов здесь один и тот же миксер Гровера с фазой
exp(-2i beta); `exact_greedy` не является вариантом с X-миксером.
Максимизируемая послойно величина — вероятность оптимума, не средняя энергия.
Оптимизатор использует beta ∈ [0, pi], gamma*sigma ∈ [-4, 4], popsize=12,
tol=1e-8, polish=True. `optimizer_maxiter` изменяет число поколений, но не
гарантирует глобальный оптимум. Увеличение глубины тоже не гарантирует
улучшение для аналитических методов.

## Проверка плана и запуск

```bash
python -m adaptive_grover_qaoa.runner configs/my-experiment.json --dry-run
python -m adaptive_grover_qaoa.runner configs/my-experiment.json --output runs/my-first-run
```

`--dry-run` проверяет параметры, печатает сочетания и общий бюджет, ничего
не оптимизирует. Если `--output` не указан, создаётся новый каталог с UTC-
меткой времени в `runs/`. Существующий каталог не перезаписывается.

`configs/quick.json` — маленький пример на 8 кубитах для проверки установки.
`configs/sweep.json` — более дорогой шаблон на 10, 12, 14 кубитах и глубинах
5, 10, 20: 90 сочетаний, 36 000 повторений, 3 600 000 шотов.
Его **не запускаем автоматически** при установке.

Используется точный классический statevector-симулятор без шума. Рабочее
ограничение генератора/runner — до 20 кубитов; время и память растут
экспоненциально. Особенно дорог `exact_greedy`: множество оценок функции
оптимизатора на каждом слое обрабатывают весь спектр. Начинайте с малого
числа seeds, слоёв и повторов; затем расширяйте сетку. Требования к ресурсам
зависят и от числа различных адаптивных целей, встреченных в сэмплах.
Независимые случаи сейчас выполняются последовательно, без распараллеливания.

## Что получается

В выбранном каталоге:

- `config.json` — точные параметры запуска;
- `metadata.json` — версии Python/NumPy/SciPy, Git-коммит, признак локальных
  изменений и хеш конфигурации;
- `summary.csv` — отдельная строка для метода на каждой задаче и глубине;
- `aggregate.csv` — средние по задачам для каждой глубины и метода;
- `depth_comparison.png` — сравнение успеха по глубине;
- каталоги `n..._k..._m..._p..._seed.../` с формулой `formula.cnf`, полным
  `result.json` и графиком успеха/остаточной ошибки по числу шотов.

`summary.csv` обновляется после каждого завершённого случая. Поэтому
завершённые результаты сохраняются, даже если следующий случай завершился
ошибкой или вы остановили процесс. Автоматического возобновления нет;
для повторного запуска выберите новый каталог или сократите конфигурацию.
Итоговый aggregate.csv создаётся после завершения всей сетки.

CSV можно открыть в Excel/LibreOffice или pandas:

```python
import pandas as pd  # необязательная зависимость
results = pd.read_csv("runs/my-first-run/aggregate.csv")
print(results[["n", "k", "depth", "method", "success_rate", "mean_fits"]])
```

`success_rate` — доля повторений, в которых **хотя бы один** из shots
битстрингов оптимален. Это не вероятность одного измерения. `mean_gap` —
среднее превышение энергии лучшего найденного решения над истинным минимумом.
`instance_success_std` — разброс долей успеха между задачами, не доверительный
интервал. Для одной задачи поле пустое. Большое repeats уточняет частоту
на этих же задачах, но для обобщения на ансамбль увеличивайте instance_seeds.

`mean_fits` включает начальный подбор углов; число пересчётов после него
равно mean_fits минус один для adaptive. `mean_nfev` — логическое число
вызовов целевой функции DE с polishing; дополнительные проверки кандидатов
из optimize_pair в него не входят. Подборы с одинаковой целью кешируются
в пределах задачи/глубины. Счётчик каждого повторения учитывает и попадания
в кеш, то есть отражает стоимость отдельного запуска, а не измеренное CPU-время.
В JSON сохраняются сами углы и время вычисления случая.

Если `save_histories=true`, integer assignment хранит x1 в младшем бите:
`(assignment >> (i-1)) & 1` даёт переменную xi. Битстроки обычной двоичной
записи показывают x1 справа. При false события адаптации и затраты остаются,
но все измеренные битстринги восстановить нельзя.

Новые результаты `runs/` исключены из Git по умолчанию. Исходные результаты
наших предыдущих экспериментов в `results/` включены для воспроизводимости.
Если хотите сохранить конкретный новый запуск: `git add -f runs/my-first-run`.
